# Pulumid

A self-hosted Pulumi HTTP state backend in Go and PostgreSQL 17, with full checkpoints, journal v1, stack-scoped authenticated encryption, and a read-only browser console. The unmodified Pulumi CLI executes your program and providers locally; Pulumid persists state, leases, history, and engine events.

Compatibility is pinned to Pulumi commit `21bf19ba40dba5dce0f565e8c614b5d8aa4dbb17`. The CLI and Go language host are built from that tree. `3.246.0` is the explicit build version label, not a claim that this commit is the upstream 3.246.0 release. Go toolchain: 1.26.5. The original detailed design is in `docs/implementation-spec.md`; implementation differences and validation limits are in `docs/supported-api.md` and `docs/test-results.md`.

## Start locally

Run these commands from the repository root. Requirements: Go 1.26.5, Docker with Compose v2, Git, and Python 3. Clone with `--recurse-submodules`, or run `git submodule update --init` first.

```sh
make dev-init
make build
docker compose up -d db
make migrate
make bootstrap
docker compose up -d api worker
make smoke
```

The API and console are at `http://localhost:8080`. Only the API port is exposed, on loopback. PostgreSQL has a persistent named volume and no host port. `.dev/master.key`, `.env`, and token files are private and ignored by Git; `dev-init` preserves existing files. `bootstrap` creates both `.dev/admin.token` and `.dev/cli.token`. Use the CLI token for ordinary deployment.

Full mode is the default. After verification, set `BACKEND_ENABLE_JOURNAL=true` in `.env` and recreate API/worker with `docker compose up -d --force-recreate api worker`. Existing journal updates remain readable when new journal negotiation is disabled. Delta is unsupported and cannot be enabled.

The console accepts an API token at `/login`, exchanges it for an HttpOnly session, and never writes that token to browser storage. Stack, update-version, and preview permalinks generated by the CLI are supported. Secrets and additional secret outputs are redacted; event text remains visible to authorized members.

## Deploy the test project

Keep the test resource world running in another terminal:

```sh
make dev-world
```

Then:

```sh
export PULUMI_ACCESS_TOKEN="$(cat .dev/cli.token)"
export PULUMI_CONSOLE_DOMAIN=localhost:8080
export PATH="$PWD/bin:$PATH"
./bin/pulumi login http://localhost:8080
cd tests/projects/basic
../../../bin/pulumi stack init demo/basic/dev
../../../bin/pulumi config set worldURL http://localhost:7071
../../../bin/pulumi config set message hello
../../../bin/pulumi config set replaceKey initial
../../../bin/pulumi config set password example-test-only --secret
../../../bin/pulumi preview --non-interactive
../../../bin/pulumi up --yes --non-interactive
```

`backendtest` is a test-only loopback provider. Automated tests install it into a dedicated `PULUMI_HOME` and use an independent persisted world; they do not touch your credentials or plugins. `make dev-world` uses `.dev/world`; stop it with Ctrl-C.

## Validate

```sh
make web-deps       # pinned Playwright/Chromium, test tooling only
make verify         # unit race tests + pinned CLI + isolated PostgreSQL/two API instances
make bench          # product binary, API storage microbenchmark; not part of verify
```

Individual targets: `test-unit`, `test-contract`, `test-integration`, `test-e2e`, `test-security`, `test-web`, `test-fault`, and `test-restore`. Each integration target creates its own named container and artifact directory, and cleans only its own processes/container. Contract/security/integration share the protocol regression suite; browser, CLI/fault, and restore suites add their respective tests. `verify` executes their combined coverage once. Failure is a nonzero exit. Evidence is stored under `test-results/<runID>/`; sensitive runtime tokens and keys are not included in source control.

Production binaries exclude HTTP fault controls. `build-test` explicitly compiles those controls with `faulttest`, enables race instrumentation, and requires a separate control token. Never deploy a test binary.

## Operations

See `docs/operations.md` for configuration, token and member administration, backup/restore, TLS, and shutdown. This version supports traditional schema-v3 IaC resources, a single durable PostgreSQL database, and multiple API instances. Remote execution, ESC/cloud config, policy packs, OAuth, delta checkpoints, schema-v4-only features, and cross-organization transfer are not supported. It does not advertise those capabilities.
